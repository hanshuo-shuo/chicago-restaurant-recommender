Protocol

Global chronological split

80/10/10 by interactions with whole days on one side. Models are trained on the past only; each query uses the user's history strictly before the query day.

Comparability

Same queries, full catalog

Every policy ranks the full catalog for the same queries and targets. No sampled negatives; no review text or demographics as inputs.

Uncertainty

User-level bootstrap

95% intervals resample users, not queries, so several queries from one user are not treated as independent evidence.

Architecture

Offline training produces versioned artifacts; the serving path loads them without PyTorch, logs every impression with its request ID, position and model version, and learns from those logs.

  1. Retrieve candidates

    Two-tower (logQ-corrected, location-aware), content, nearby and most-popular sources score the full catalog exactly and are merged into about 220 candidates.

  2. Apply constraints

    Hard filters for cuisine, distance, price and hours; closed restaurants are excluded. Unknown metadata never satisfies a filter, and an empty result is explained rather than silently relaxed.

  3. Rank

    A LightGBM ranker, objective chosen on validation, scores the candidate union with retrieval scores, distance, price fit and cuisine affinity. A fixed blend is the fallback arm.

  4. Observe

    Log impressions with request, position, scores and model version. A click or favorite is accepted only if it matches a logged impression from the same session.

Event store

One request, traceable signals

SQLite (WAL), anonymous session UUIDs. Events join impressions on request ID, so every click names the arm and slot that earned it.

Cold start

Ask for taste, then collect signals

New users pick cuisines, a neighborhood and seed restaurants. New items are retrievable on day one through content features and Semantic IDs; no user-ID embedding is needed.

From logs

Debiased learning

Impression logs feed a multi-task (click, favorite) ranker whose shallow position tower absorbs position bias, so the learned ranking reflects utility rather than slot.
